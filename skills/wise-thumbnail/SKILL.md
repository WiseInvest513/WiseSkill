# Wise Thumbnail

封面让观众快速识别“讲什么、为什么值得点开”，同时与视频内容的设计质量相称。先决定一条主命题，再安排文字和主体；不把视频目录或所有实体挤进一张图。用户最新指示、已选择的封面方向优先。

## 接入与复用

- 读取本期标题、成片/文稿或校正字幕及现有风格记录。已有完整内容时自行提炼，不要求用户重写摘要。
- 找到已确认封面模板时，读取其 manifest，沿用字体、品牌位置和核心层级，替换本期命题、文案与主题主体。不要每期重新要求用户三选一；新主题确实不适合模板时再提出局部变体。
- 首次设计或用户要求探索时制作 2–3 个有意义的方向，差异可以来自主体关系、文字位置与信息节奏，不需要每版换一套品牌气质。比较时保持核心文案与事实含义一致，以便判断设计；只换颜色不算不同方向。
- Wise 已确认封面默认版式是左侧放大圆润标题、右侧仅保留既有地球背景，额外物件按最新反馈撤掉；先保证第一眼读清主题。具体参数及模板依赖见 [Wise 封面布局](references/wise-series-layout.md)。整体仍需优雅、适度表达内容、与片内视觉一致。优先看本片实际画面，复用确认背景、已验收立体物件、准确 Logo 和署名，再按封面重新构图。片内截图并不自动成为封面；也不要无依据另造一套高冲击营销风格。

## 发布标题入口

用户要求视频起标题、修改发布标题，或交付完整上传版本时，读取 [发布标题与数据核验](references/publish-titles.md)。中文中长视频当前默认30–40字、一个推荐标题，完整交代当下处境、核心疑问与观看价值，让真实数据支撑主线；核对数字主体、时间与口径，保留原文条件。只要标题时完成文字与证据即可，不启动出图或视频渲染。封面与标题一并交付时共享内容主命题，互相补充。

## 1. 从内容选出封面命题

先在本期工作区记一份简短 `cover-brief.json`，包含：

- `source`：输入路径或来源；`audience`：这期面向谁。
- `promise`：视频实际回答的一个问题或提供的具体帮助。
- `evidence`：支撑主命题的原文段落/字幕范围；`uncertainty`：必须保留的条件、否定或问句。
- `copy`：主标题、可选补充词、系列/日期；`visual_relation`：主体之间的关系与第一眼焦点。
- `identity_assets`：确实需要上封面的品牌/人物及已核对的真实文件；`gaps`：只列阻碍本封面制作的缺口。
- `style_state`：`candidate` 或 `approved`，以及已确认模板路径（有才写）。

区分“内容里提到”与“封面要表现”：通常保留一个整体主视觉，可由2–3个有关系的信息支点组成，不必只放一个孤立大物件。公司身份用真实 Logo 或准确名称；宏观概念可用适合的原创隐喻，不能用通用芯片冒充某一家企业。

标题优先 1–2 个短句，以手机尺度能读清为准，不以固定字数代替判断。副文案仅在增加新的点击理由或明确范围时使用，不能复述大标题。日期只在时效性影响理解时出现。

## 2. 设计固定品牌层与可变主题层

**品牌层**记录署名/头像、字体、基础配色、文字层级、保护区及允许的布局变体。**主题层**记录本期短标题、物件/人物、关系、日期与必要数字。模板锁定的是这些设计约定，不锁定某期股票、日期或涨跌判断。

- 一眼先理解主命题和主视觉的联系，其次才是补充信息；不能让署名、日期或装饰抢主焦点。标题与主题画面需要平衡，没有固定的标题面积比例。
- 标题与主体形成明确关系。Wise 采用有力度的左侧大字，但不使用夸张的金属巨字；避免多处散落的小标题、等尺寸卡片平铺。素材可以稍丰富，但要有层级和真实关联。背景负责衬托；用户明确选择纯文字主视觉时，不强制添加右侧物件。
- 不默认使用惊讶头像、金属巨字、发光大箭头、夸张暴跌、强对比黑金。它们不是“适合YouTube”的通行证明；只有用户另行选择且内容合适时才采用。
- 为底部尤其右下角的播放器时长标记留余地。实际保护范围通过缩略图检查，不写死成所有平台通用像素。
- 金融曲线、箭头可表达“压力、疑问、分歧、潜在转折”；没有真实数据时使用明显概念化的形态，不生成带虚构刻度、价格或日期的仿行情图。原文说“可能反弹”就不能改成“必将暴涨”。

## 3. 取得素材与生成候选

- 检查现有真实头像、署名与公司 Logo，优先复用。用户人物身份和精确 Logo 不让模型凭记忆重画；缺少关键身份素材时用准确名称或说明缺口，不能冒充已取得。
- 有合适已验收素材时，可将原封不动的 PNG/SVG 放入 HTML/CSS 等精确排版组合，导出新的封面；这是构图，不是改动素材像素。保留原文件与身份准确性，避免为“新封面”重新生成整套成熟物件。
- 真正缺少的原创建模、纹理、金融隐喻或构图草案才使用可用的 image generation 工具；若有 `imagegen` Skill，按其要求执行。生成提示写清主体、层级、文字位置、材质、配色、留白和禁止的误导信息，不只写“高级好看”。
- 中文必须逐字检查。可以先生成视觉底图，再用可控的排版方式放入准确中文与真实品牌素材；工具规则要求图像编辑走图像生成时遵守该规则。不用未经核对的生成 Logo 或脸替代原件。
- 把候选、制作源与检查小图存本期 `projects/<episode>/`。不覆盖原件；不把所有试稿收进共享模板。

## 4. 看实际图片再交付

每个候选至少打开检查完整图和 **320×180** 的缩略图；多候选展示时保留单张实际小图，不只看自动放大的合集。记录结果与修改，不用提示词或文件生成成功代替视觉验收。

1. **手机可读**：不用放大能读清主标题，核心字不拥挤、不被主体遮挡；补充词确实有用。
2. **含义与身份**：图文说的是同一件事；中文、人脸、Logo、数字无错；条件与疑问没有变成保证。
3. **画面完成度与系列一致**：边缘、光线、比例、重复/畸形物件、人物裁切、文字对比和右下角时长遮挡检查通过。与本片实际优质画面对照：材质、配色、署名和内容感是否一致；可读但金属特效过强、与正文质感脱节仍视为视觉未通过；不要因为用户否定某次巨字就把主标题一律缩小。
4. **文件可上传**：检查真实尺寸、格式、字节数和16:9比例。平台规则会变化；需要声称“符合当前平台规格”时查官方帮助。可按用户需求交付高分辨率 JPG，并另存 ≤2MB 兼容版；≤2MB是兼容策略，不是所有设备的统一官方上限。

没有实测点击数据，只能说可读性、辨识度和内容匹配经过检查，不能宣称点击率更高。

## 5. 选择、保存与视频交付衔接

- 首轮交付实际候选图，让用户选方向；未选择前标 `candidate`，不能登记“已确认封面模板”。有已确认模板的日常新封面，完成检查即可交付，无需重复等一次风格批准。
- 用户选定后，把本期可上传封面放 `exports/<episode>/`，名称有版本。把最小可复用资源、布局参数与 manifest 收敛到 `assets/templates/`；参考 [模板登记与验证](references/template-record.md)。原始头像和 Logo 仍保留在原件库。
- 在视频交付中调用本 Skill 时，读取该片校正字幕与命题后生成封面，不重新修改视频内容。用户只要求设计封面就只交付封面，不顺带上传到平台或推送仓库。
- Skill 在其他工作区分发时，附带必要模板资源或准确说明需用户提供的品牌素材；使用相对路径，不依赖作者机器的绝对路径或已删除的项目。
- 清理只按用户授权范围进行。保留最终封面、原件、已确认模板和简短索引；不要为归档复制整套候选与大缓存。

创建或较大改动本 Skill 后，参照 [跨主题推演](references/behavior-cases.md) 检查决策。文字推演不能替代实际出图与320×180实看。
