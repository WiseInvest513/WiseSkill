# 完整视频发布套件

用于可上传完整视频的配套交付：默认自动完成，不等用户逐项提醒。制作顺序是先完成封面优化与检查，再写简介，简介后紧接真实章节目录；同时准备一个推荐发布标题。用户已确认的决定及本次明确范围优先。仅要标题、封面、字幕或局部样片时只做该项；明确只要视频时不扩大任务。

## 先选内容模式

同一 Skill 内维护两套发布标准，复用共同规则，不让系列和教程互相覆盖：

| 模式 | 识别依据 | 标题 | 简介 |
| --- | --- | --- | --- |
| 系列内容 | 如纳斯达克投资系列，解释某一期的概念、数据或方法 | 约30字，通常28–32个可见字符 | 默认200–300字，清楚交代本期问题、主要发现与观看价值；本期要求更长时遵从用户 |
| 产品教程 | 介绍一个产品，讲功能、开户/操作、成本或福利；即使有期数，也按实际内容判断 | 约50字，通常45–55个可见字符 | 500–600字，一个完整自然段，有开头、展开和收束 |

教程简介顺着观众需求展开：手里有什么资产、材料或待解决的问题 → 本期介绍什么产品 → 主要功能及能实现什么 → 视频会演示哪些关键操作和成本 → 有哪些已核实的优惠及领取条件，最后自然引导观看或收藏。缺少优惠的产品不硬写福利；未在视频讲到的功能不为凑字补入。不要把这些提示变成五条机械清单，也不要把“500–600字”写成多段零碎说明。

本表用于视频发布介绍；用户另要评论区一句话或X推广帖时按实际平台与篇幅写，不自动复制长简介。标题、简介和封面先提炼同一个主命题：教程应说明产品替观众解决的核心问题，流程和奖励用于补充，不让泛泛的步骤清单取代卖点。

## 内容与次序

- 读取最终成片、校正字幕、最终时轴和当前封面反馈。封面沿用已确认的超大标题与右下角适度地球版式，默认制作16:9、3:4、4:3三张，各自排版与检查，尺寸见[Wise封面布局](wise-series-layout.md)；明确只要某比例或先看样稿时遵从本次范围。发布标题依照 [发布标题与数据核验](publish-titles.md)，使用上表对应长度，交代真实行动或处境、核心结果/用途和观看价值。
- 标题与简介按上表计数：中文按字，英文字母、数字和标点各按可见字符计数，空白及章节目录不计入；用脚本核对长度，不靠估算。按本期内容自然引出最吸引人的具体命题，带入有来源的数据或适用条件，并说明视频真正讲解的价值。不能每期照搬某次选举、胜率、品牌、奖励金额或投资主题；字数达标不等于内容完整。
- 数据或条件须能回指已核验一手资料或用户原文中的适用条件，记录来源及对应片段。核验外部数据时沿用标题的数据核验口径。缺数据可用真实且有出处的适用条件，不捏造数字；无法证实的内容删去或说明缺口。问号不能替代统计样本、观察区间、买入窗口与持有期等必要限定；历史100%结果必须说明样本和条件，不暗示未来保证。
- 章节只列视频真实讲到的段落，从0:00起、按最终成片绝对时间递增，标题准确简短。拼接分段、插入开场/片尾、裁切或改速后，重新对照最终MP4及字幕核对各章起点与总时长；不直接复制分段相对时间，不按文稿猜时间，不虚构章节。未取得最终时轴时标明待核对，不能声称发布包已完成。

## 保存与直接交付

最终文字按“推荐标题 → 对应模式的简介 → 章节时间目录”排列，简介后紧接章节；三种比例封面作为独立可上传文件一并交付（用户明确缩小范围时除外）。回复给出可直接复制的完整文字和实际文件，不只介绍写作方案。

- 完整文字统一保存为本期实际导出目录中的`介绍.txt`，例如`exports/<episode>/介绍.txt`；系列沿用既有系列/期目录。内容顺序固定为“标题→简介→真实章节”，默认不另建重复的发布包TXT。
- 封面：按期放入`exports/<episode>/`，采用“中文期数-主题-比例.jpg”，如`纳指投资第一期-买纳指到底买什么-3比4.jpg`；另两张分别标`16比9`、`4比3`。仅预览的样稿留在本期工作区。
- 默认不重复生成独立标题、简介或章节TXT。机器读取的章节JSON、字数与事实核验记录可放本期工作区或维护记录，不挤入可直接复制的`介绍.txt`。
- 在小型记录中保存标题与简介计数、数字/条件来源及最终时轴核对结果。已有确认文字需要保留时，按明确版本名保存新稿；用户授权替换后以`介绍.txt`作为当前完整文案。用户授权清理时，可删除被其完整替代的本期重复旧文案，不扩大到其他期、原件或已确认成片。未确认新封面保持candidate，不因发布包已生成就登记成approved模板。保存或交付不代表获准上传平台、发布或推送仓库。
