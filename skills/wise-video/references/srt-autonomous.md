# SRT 驱动的自主制作

适用：用户提供字幕（可附单独原声），要求按指定范围自动生成画面、样片或成片。统一入口是 WiseVideo（`wise-video`）；用户不用把中间文档复制到别的 Skill。默认沿用当前项目已确认的背景、署名、开场和历史授权；个人包资源与新工作区的路径配置见 [运行依赖与路径](runtime-and-paths.md)。只要求解释流程时不启动渲染。

## 一次输入，内部完成

用户通常只需提供 SRT、范围（例如前约5分钟）、可选原声。将工作放入新一期目录。用户已授权自动制作时，语义计划、素材匹配、分镜、制作、检查和修复在内部连续执行；不要求每一步重新确认。真正影响含义的歧义、无法确定的音频对应关系、关键精确素材或外部发布才按实际情况处理。

### 1. 接入与时间真源

用 `scripts/srt_intake.py` 保存全文和范围清单，读取 `intake-report.json`，同时核对status与effective_range_content_complete。原 SRT 是文字与时间的真源，不改写成新的旁白；用户说“根据 SRT 生成文案”时，在视频任务中默认指分镜/屏幕表达文案。只有明确要求重写口播时才另写建议稿。

- 只提供24秒而要求前5分钟时，先完成已有24秒，不补写或硬撑到5分钟。whole-cues实际范围不得超出已提供字幕末尾；exact超过源内容须明确pending，不能声称完整时长已满足。保留requested与effective两个范围。
- 固定开场只在原文包含对应问候或用户明确要求插入时复用；不能自动加到所有短SRT。
- 读全文理解上下文，再制作目标范围。字幕条目可能只是半句话，先合成语义意群。不能把字幕数量当句子数量。
- “约5/10分钟”默认保留边界完整条目，再判断是否还需相邻条目才能完整表达；记录实际范围。明确严格时长时使用 exact，并标出截断风险。
- 重复、乱序、疑似识别错误原样保留并另记，不能为了过检查删掉。
- 计划和素材索引使用源绝对毫秒；最终视频用局部时间 = 源时间 − 实际起点。只转换一次。
- 只有SRT：继续规划、素材、静态或无声预览，不合成替代原声。单独原声可稍后加入。
- 音频映射明确记录 `audio_time = srt_time + offset`。同源导出证据、用户说明或实际声音核对可建立映射，文件名/时长相似不够。不靠拉伸或删字凑同步。

调用示例（秒）：

```sh
python3 scripts/srt_intake.py EP/input/captions.srt --duration 300 --out EP/intake/run-001
python3 scripts/srt_intake.py EP/input/captions.srt --audio EP/input/voice.mp3 --audio-offset 0 --duration 300 --out EP/intake/run-002
```

第二条仅在同源零点已有依据时执行。工具检查只证明映射范围合法，不证明声音内容已核对。

### 2. 理解先行，画面以变化承接

读取 `analysis-workflow.md` 与 `visual-direction.md`，对每个意群先写“观众看懂什么”，再确定主画面、稳定主体、镜内展开、上屏短词与实际改变的维度。按输入选择媒介与构图，不固定用三栏白卡。别把几句通用验收文案批量复制到所有 beat。

重点区分：

- **整体与子集**：说某一类的选择增多，先明确聚焦对象，再让该对象下的选择增加；不能先删掉大多数对象再声称“增多”。
- **否定与数量限定**：“不是所有人能改”不等于“所有人都不能改”。保留被否定的范围，不自行指认权限、归属或例外。
- **关系类型**：同一条箭头可能被读成转移、兑换或因果。支持/担保/依赖类关系必须保留两端并用短标签或结构消除歧义；需要否定时让被排除的对象与保留对象可比较。
- **过程与过渡句**：回溯、引导、转折、导航同样安排可见主体。按逐句状态决定旧对象去留：必要锚点交接，解释任务已结束的载体退场，剩余重点重新构图。不得一律规定旧主体必须等新主体完全出现才退出；同区域换意时先让位，相关变化才短暂同屏。
- **独立受众与评价**：单独提出的目标用户、体验或条件要有对应焦点状态；不能借整场Logo/手机一直可见来声称这句话已承接。
- **焦点与清晰度**：突出当前项时，前景衬底不要跟着降低透明度而暴露复杂背景。可用标记、局部颜色、大小或图形内部变化；静止参照也需要能读。
- **平台身份与产品性质**：Logo识别平台/公司，凭证、支持链、合约解释资产性质；Logo不替代权利说明。概念界面标为示意，不冒充真实操作页面。

为全部目标字幕填写原有 `coverage` 和 `render_bindings`（见 `handoff-contract.md`）。逐条说明承接职责和有意停留原因，不能把所有句子机械绑定到一个平台Logo。核心解释图应该在实际播放器尺寸下可辨认；仅有对象存在不算完成。

完整叙述由原声/字幕承担；主画面保留帮助识别与理解的短词，内部核验意见不自动上屏。不要生成一条常驻“制作说明字幕”。具体事实冲突保存在审阅文档中单独处理，不用新的长解释掩盖问题。

### 3. 素材与实现

先审完整实体和主视觉形式，再匹配用户库、已核准资产和代码可绘制的关系图。缺少同组相容的主物件也算素材缺口，不能默认降级成线框白卡。已有补充授权就直接生成通用物件；精确 Logo 从用户/官方来源取得。具体权限继承 production-controls，不因自动模式扩展到公开发布。

先用本片代表镜头完成少量真实 PNG 和主要展开态，实际看图并修正材质、尺度、文案及组织问题；记录 `design-review.md`。静态到动画按 [设计到动效](design-to-motion.md) 锁定实际资产与构图依据，检查独立部件，验证主要动作的前/中/后态和原声落点，再扩展整片。以同一 semantic_plan 驱动场景、对象和动作。通用渲染脚本接口见 `render-adapter.md`。结构校验与 `audit_visual_plan.py` 候选审阅后编译，再校验接线；手动改变实现须回到计划同步，不维护第二套隐藏事件。

### 4. 自审、修复、交付

自动模式也必须审实际画面：

1. 原始内容/时间/资产/接线检查；不能漏掉难画的句子来通过。
2. 每个意群抽取稳定帧，重点动作看前、中、后；每条字幕中点检查有相关可见主体。再沿相邻完整句逐一检查新增命题、本句焦点和旧元素去留；独立受众/评价/条件缺表达、任务结束的载体仍抢画面时，语义审阅不得通过。中点检测只抓漏项；另做实际图的语义与审美审阅，比较主视觉完成度、图文归属、整组平衡与镜头变化，不只查看几何告警。
3. 高风险转场和移动重排加密到0.1秒；扫实际边界，并人工区分有意叠放与透明SVG误报。允许相交必须写具体对象、时间与原因。
4. 数量增长验对象数，趋近验距离，转移验路径与抵达，支持验两端保留，导航验游标与目标同步。不要沿用旧坐标/旧验收数值。
5. 检查原声保留、起中末时机、输出时长、音轨与完整解码。没独立听审则如实记录。
6. 修复实际失败后只复查受影响片段与相邻转场；一般最多连续修复3轮同类失败，仍失败时给出可看的阶段结果、问题和所需信息，不无限循环，也不把失败写成通过。

用户明确要求多轮迭代时，每轮必须完成真实输出与审阅后，再基于发现制作下一轮；研究与工具工作可以并行。默认新一期不机械做三版，按用户范围完成一版并自修。

最终交付可看的结果、简短差异与残留限制。详细数据留项目 `qa/`。不把“80%”当精确评分或普适质量保证；区分流程覆盖与新题材表达仍待验证。

## 接口与状态

- intake → source captions/range + checklist（pending）
- semantic_plan → 原有beats/coverage + render_spec + render_bindings
- compiler → index.html/cue_sheet/provenance（所有素材本地冻结）
- validate_handoff → 机械接线 passed/pending/failed
- qa → 语义、静态、动态、声音、技术各自结论
- output/preview → 最终结果与历史对照

接线/原文检查通过，不能替代其他层。细节见 `handoff-contract.md`，方法来源和实际回归见 `external-methods.md`。
