# 目录与精简归档

用户希望以成片交付为中心，避免不断保留测试、重复素材和中间工程。本文件约束保存方式，不改变画面设计和内容分析流程。

## AView 工作区约定

| 位置 | 用途 | 修改规则 |
| --- | --- | --- |
| `.agents/skills/` | 本项目实际调用的正式 Skill | 不作为缓存清理；功能更新按用户要求执行 |
| `skills/WiseSkill/` | GitHub 分发仓库，含本地修改和 Git 历史 | 不当作旧测试删除；不自动推送 |
| `assets/originals/brand/` | 背景原图、Telegram 群图、署名和头像原件 | 原件保留；需要改图时复制到本期工作区 |
| `assets/originals/<episode>/` | 本期用户提供的音频、字幕及用户要求保留的原件 | 原件不覆盖；修改版另存 |
| `assets/library/` | 已验收、可重复使用的派生物件与系列索引 | 与原件/固定模板分开；新版不覆盖旧条目，未验收候选先留本期 |
| `assets/templates/` | 已确认的背景、开场、片尾模板 | 先读 README/manifest；不要因本期制作悄悄改变模板 |
| `projects/<episode>/` | 当前制作的可编辑工作区 | 测试、素材派生图、QA和渲染中间件都放在本期，禁止散落根目录 |
| `exports/<episode>/` | 最终交付的视频和校正 SRT | 确认版不覆盖；新版本使用明确版本名 |

其他工作区可沿用相对结构。已安装的 Skill 资源或用户指定目录优先，不依赖作者机器的绝对路径。

## 制作与收尾

1. 先匹配共享原件与模板，仅将需要的资源复制到当前工作区；不要复制整套旧测试项目作为新一期起点。
2. 调试时保留用户选定基准与当前候选，避免每次修正都复制完整项目。所有临时文件留在本期工作区。
3. 最终 MP4/SRT 放入 `exports/<episode>/`，核对时长、分辨率、播放及文件哈希后才处理旧输出。
4. 本项目用户选择精简归档：认可成片并明确要求清理后，保留成片、原始音频字幕、指定原件及通用模板；删除本期测试导出、重复素材、QA截图、渲染缓存和不再需要的编辑工程。不要把这次授权扩展到其他项目、共享原件或云端文件。
5. 归档记录只保留简短清单与哈希；不要为了归档再次复制整套大目录。同步目录说明和继续位置，删除后不再指向不存在的工程。
6. 精简归档不等于保留可编辑工程。之后若需要大幅修改，使用原始输入和模板重建；不能承诺所有旧镜头源仍然存在。

## 可复用派生素材

用户明确要求保留复用素材时，生成候选和编辑过程先放本期，检查透明边缘、实际播放尺度与同组材质后，将可用的独立物件收录 `assets/library/<collection>/`；采用已有共享库路径也可，不新建平行重复库。只有需要时才保留分层部件，避免复制整张测试画面。

索引最少登记：稳定 asset_id、版本与相对路径、文件哈希、来源/生成提示与风格参照、可表达的角色或关系、不适用含义、透明/尺寸及必要可动部件。例：纸钞束可承接现金数额，不自动代表 USDT、收益保证或银行；中性人物可承接操作人，不是用户证言。准确品牌另用官方素材，不把仿造 Logo 收作通用图。

本期素材索引引用共享 asset_id，制作时可按引擎需要链接或复制单项，并记录实际文件哈希。库中“可用”只代表该物件已检查，不代表任意组合、具体命题或动效都已验证。共享库与原件一样不进入默认测试清理范围；替换、精简仍按用户实际授权。

## 已确认模板

AView 当前模板位于 `assets/templates/wise-background-approved-v1/`、`wise-intro-approved-v2/`、`wise-outro-approved-v1/`。开场和片尾仅在对应话术存在或用户要求时使用；模板内容与本期事实分开。Telegram 群图等原件位于 `assets/originals/brand/`。分发版对应资源为 `SKILL_DIR/assets/background/`、`assets/intro/`、`assets/outro/`，Telegram 与片尾头像位于 `assets/outro/assets/`；优先使用这些随包资源，保持相对路径，不依赖 AView 历史项目。
