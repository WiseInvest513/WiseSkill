# 项目制作控制

本文件承接原视频流程的约束，与内容理解方法一起执行；不属于文章写作规则。用户最新明确决定优先。

## 项目恢复与范围

文件组织与用户授权后的精简归档，见 [目录与精简归档](workspace-layout.md)。

- 根目录使用用户当前工作区；每期建议放在 `<workspace>/projects/<episode_id>/`，保留原输入和历史版本。所有命令路径以本次工作区和 Skill 安装目录为准，不依赖作者机器。首次运行先读 [运行依赖与路径](runtime-and-paths.md)。
- 开始/恢复先读本期 `workflow_state.json`、`approvals.json`、视觉规范、原文及 `asset-index.json`（文件存在时读取）。历史样片仅供参考，不代表下一期内容。
- 扩时、加段落、换音频/字幕：重新覆盖新增实体、条件和动作，更新计划范围后检查。不得排除未规划段落来通过检查。单项修改只处理依赖场景。

## 已选版本上的增量修改

- 在状态中分开记录 `active_baseline`（用户选定版本）与 `latest_output`（最近生成文件），附计划/成片路径及用户决定。两者可能不同；被否定的试稿保留为历史，不自动成为下一次起点。
- 实现前列一份短变更清单：目标时间/对象、当前问题、修改层、具体改动、需要保留的资产/布局/动作、依赖范围。用户已经授权的局部改动直接执行，这份清单用于控制实现范围，不额外设置批准关卡。
- 尺寸、间距或融入感问题先调整占比、留白、位置与进入时机；只有用户要求或证据确实指向风格问题时才重设计。已接受的素材、构图、关系动画和节奏继续复用。需要改动依赖对象时说明原因和范围。
- 增补图像服务于尚不清楚的实体或关系。有效的卡片、SVG、代码图解与插图可以共存；不要为了降低卡片数量批量替换已经讲清楚的场景。新增图匹配基准的材质、光照、配色和实际显示尺度，关键文字/关系仍保持可编辑。
- 验收同时回答“改动处是否更好”和“保留处是否被误改”：检查改动区间及其进出场；比对代表性未改场景与原素材引用。出现非预期差异先定位并修复，不能仅凭新版能播放就通过。
- 交付状态与执行证据分开记录：规则已写入且已校验、实现文件已修改、样片已生成、成片已检查分别记实。只更新状态或决定记录时，应明确视频和Skill尚未修改；预览链接必须对应实际产物。

## 素材审核与授权

- 第一遍原文得到完整实体；第二遍库存匹配得到缺口。`asset_requests.md` 分品牌/产品精确标识、通用插图、代码元素，记录位置、用途、候选、缺少项、补充方式。
- 集中告诉用户真正缺少什么，让用户先提供。未回复不等于不能提供，不抢先生成或下载。若用户已经明确说剩余素材自行补充，按该范围直接继续，不再询问同一事项。范围不会仅因新实体出现而自动扩大。
- 通用插图缺失且已授权时，先准备准确提示词再使用生成工具。品牌/产品精确标识不AI仿造；缺失时请求准确文件或按授权从可靠来源取得。默认不下载外部素材或上传用户文件。
- 核心身份素材不得静默文字替代；用户接受文字替代时记录真实原话。非关键名词可有理由地不配图。
- 打开图片核对实际实体、品牌版本和用途，不能仅靠文件名。例如文件名“黄金”实际是BTC；带US的币安图存在版本差异。发现真实错配时说明，用户明确接受特定用法后记入批准，不反复追问。
- 登记原路径、项目副本、哈希、实体及状态。`asset-index.json` 是素材状态真源；manifest引用asset_id，不复制长期漂移的批准状态。批准绑定哈希与用途，脚本不得覆盖人工批准文件。静态方向还需记录设计源、实际截图与关键布局依据；进入动画时沿用它们，具体交接见 [设计到动效](design-to-motion.md)。

## 已确认背景与视觉约定

- 本个人完整版随附定制背景与署名：读取 Skill 内 `assets/background/README.md` 及其 manifest，直接复用冻结版本。通过 `--background <skill-dir>/assets/background` 显式传入；用户选择自己的背景时改为其路径并记录来源。
- 沿用随包风格时保留白底、10%圆角的小署名；不回退大图、正片叠底或自行重新设计背景。可选开场在 `assets/intro/`，只在内容确实包含对应开场或用户要求时显式传入，不能自动插到所有视频。已确认红色大订阅片尾位于 `assets/outro/`；先读其 README，根据本期结尾话术对齐时间，不复用历史录音。
- 冻结背景约束其文件复用，不把背景地球变成正文避让区。用户最新明确要求居中/移位时，记录为待实现的新背景变体，保留原模板；正文仍按整幅画布设计。只改Skill时只更新规则和项目决定，不立即改背景或成片。
- 延续当前项目已接受的立体金融风格。内容画面默认不新增人物或纸币肖像；已确认署名照常复用。用户明确要求用人物表达受众时，可按授权用途使用中性、抽象人形，不据此为其他段落或后续视频自动加入真人、卡通主持人。其他主题使用其已确认风格，不强制金融风格。
- 精确文字、数字与标识独立排版。素材应在实际显示尺寸下清晰，不能用放大低清图来解决可见性。

## 原声、字幕与信息完整性

- 原录音不改语速、不删旁白；原字幕保留，识别问题另记。只有另获用户授权才改写。
- 句级时间戳不冒称词级。并列名词可整组出现，后续依次强调属于编辑节奏；要求精确词同步时核对音频。
- 原词、别名与身份分开：疑似转写错误先看上下文，不把含混口误造为新产品。影响表达且无法判断时核对。
- 示意产品增多不代表真实产品数量；不虚构价格、收益、因果、成交保证或背书。图表尺度与数字需要依据。
- 上屏文案不是审稿记录。内部来源、待核条款、资产限制留制作文档；不默认给每场加注释条，不用“口播称”等字眼对观众解释工作状态。用户最新删除决定要覆盖旧的上屏批准，历史记录保留但不能偷偷回填。必要的账户/费用适用范围、币种和否定短词按语义贴近对象；具体取舍见 [视觉设计](visual-direction.md)。

## 实现与交付

- 字幕驱动制作按 [校验契约](validation-contract.md) 使用本Skill的校验器。完整语义分析保留角色、关系、限定和表现理由，不能缩减为校验器最低字段。
- semantic_plan → cue_sheet → 实现适配器，保留输入/计划哈希。改动一个计划动作，确认实现输出随之改变，证明计划确实接入。
- 默认先做代表镜头的实际 PNG 与主要展开态，完成看图—定位问题—局部修正—复看。静态到成片之间按 [设计到动效](design-to-motion.md) 验证主要动作的局部原声样片，再推进整片。已经授权自动整片时内部执行这些步骤，不额外加确认；只改 Skill 时在测试目录按授权范围验证，不修改正片。禁止自动发布。
- 技术、语义、审美、动态分开记录；实际图片对照已认可参考，语义对照前/中/后状态，旁白同步另记。没有遮挡不代表有设计；未执行的检查标未验证。用户否定的片记为视觉失败，不能保留笼统“全部通过”状态。
- 恢复时以磁盘和最新用户决定为依据；归档日志，不以口头承诺替代执行证据。
