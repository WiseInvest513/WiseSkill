# 从已认可素材到可验证的动态成片

在静态方向转成动画、重做成片或升级制作方法时读。本文件负责设计与动画的交接；语义选择见 [视觉设计](visual-direction.md)，具体空间检查见 [布局与生命周期](layout-and-lifecycle.md)，不另建用户入口或要求逐步手动确认。

## 一条连续的制作链

**理解元素 → 设计并取得元素 → 验收素材与构图 → 编排并实现动作 → 渲染成片 → 按实际失败修订方法。**

每步使用上一步的产物，不把整幅已批准静态图直接当作唯一可动层，也不在动画阶段重新发明一套风格。用户批准静态方向且要求制作时，继续完成动态验证和成片；静态批准不是动态通过。用户只要求静态图或方法升级时，停在相应交付范围。

| 交接 | 必须确定的事 | 推进依据 |
| --- | --- | --- |
| 原文 → 元素 | 主体、承载物、关系、变化及条件；图比字幕多解释什么 | 对象与原句有具体关系，不能互换标签仍成立 |
| 元素 → 文件 | 精确身份/地点与可生成物件分开；谁需要单独运动 | 本地可用资产、来源、哈希、透明边界及可动层 |
| 文件 → 构图 | 同组材质、实际显示尺度、阅读顺序和主次 | 实际 PNG 和主要展开态通过看图检查 |
| 构图 → 动作 | 哪个部件在何时改变什么，结束后谁保留 | 与原声相符的前/中/后状态及实际运动记录 |
| 动作 → 视频 | 最终尺寸、帧率、原声、字幕和范围 | 检查真正编码后的文件，而非只检查浏览器 |
| 失败 → 方法 | 是素材、关系、布局、时机还是执行问题 | 一个最小修复、实际复查、可适用的新场景边界 |

## 1. 把静态批准绑定到具体产物

在本期现有状态/批准文件中记录一份设计锁定清单，不再创建互相漂移的批准真源：

- **范围和依据**：用户选定的版本、截图路径/哈希、对应原文范围，注明是“静态方向”还是某张精确构图获得确认。内部通过不能写成用户批准。
- **资产依赖**：背景、署名、主体的 `asset_id`、本地路径和 SHA-256；准确品牌图保持来源与用途记录。
- **构图依据**：设计源文件、画布尺寸、关键主体的可见大小/锚点/归组、独立文字层、使用字体及备用字体。可记录源文件哈希加布局摘要，不要求复制所有 CSS。
- **保留项与可变项**：哪些材质、主体、关系和终态要保留；哪些位置、尺度、入场方式允许为动作调整。用户认可一组静态方向不等于冻结每个像素；必要动态重排须有理由并检查新的终态。

资产哈希变化、主体替换、字体替换或终态重排时，只重新验证受影响镜头。不要直接沿用旧截图的批准覆盖新文件。普通时间调整不触发整片重设计，自动授权下在内部完成复查。

## 2. 素材要同时满足“看得清”和“动得对”

生成/获取之前先写各元素的动作职责。把同一个对象拆成独立部件，仅在它们确实需要相对运动时才有收益：例如文件从设备外进入设备，需要文件和设备分层；讲组合成员增加，成员不能永久烘焙在一张合照里。

### 按职责分层

- 背景、准确标识、主体物件、可动部件、短标签、关系线和强调效果分别保持可编辑。
- 每个主要层记录 `asset_id → scene/object_id → 可动部件 → 允许的动作`。保持同一对象跨句的身份，不能每次强调时重新生成另一张相似图。
- 只有整体入场/轻微聚焦时，完整物件可以是一层；不要为“可编辑”强行切割所有纹理。若承诺打开、翻页、转轴等内部动作，却没有部件/3D模型/相应姿态素材，就回到素材阶段补齐或选择同样能讲清含义的动作。
- 2D 物件的平移、有限缩放和遮罩揭示可用；不要把平面插图旋转成露出不存在侧面的大幅 3D 转体。真实地点、数据图及品牌字标不交给生成模型猜测。

### 素材验收发生在最终背景和实际尺度上

先检查透明边缘、白边/脏边、比例、可见轮廓、阴影、光向及同组完成度，再检查每个预期动作需要的遮挡层和留白。按可见 alpha 轮廓定尺度，不能按透明文件方框估计主体大小。精细物件缩小后辨认不出，应改构图或简化资产；不能继续加字补救。

新图验收通过后登记为可用；“文件已生成”“文件可解码”与“适合这镜”分开记录。缺主物件时不能让一个临时占位符进入最终渲染。

## 3. 把动词变成可观察的状态差异

在现有 semantic_plan 的动作和验收说明中补齐下面的证据，不另维护第二套隐藏事件。高价值动作可以用一行表记录：

`原句/关键动词 | 稳定参照 | 前态 | 变化部件与参数 | 后态 | 实际取帧/测量时间 | 结论`

例如：

| 讲述含义 | 前态 → 变化 → 后态 | 证据应看什么 |
| --- | --- | --- |
| 同类归组 | 原有对象分开 → 同类靠拢、共同边界出现 → 规则短词归属于这组 | 组内距离实际变小、异类仍分开，对象身份未换 |
| 交给另一主体 | 载体在起点 → 沿有依据的路径移动 → 接收侧出现结果 | 起点、途中、抵达均能追踪；不是两端各淡入一个副本 |
| 选择增多 | 有限成员 → 新的可区分成员加入 → 同一集合更丰富 | 后态可见成员确实更多，没通过先删旧成员制造假增长 |
| 回到过去 | 保留“现在”参照 → 时间轴/指针逆向移动 → 过去状态成立 | 时间方向可辨；不把整页任意旋转当成时间回溯 |
| 展示地点 | 全域轮廓 → 对应区域聚焦 → 主体与区域关联 | 位置准确且可读；缩放后仍有足够地理参照 |

这不是要求逐句都移动。解释、比较和停顿可以稳定展示；其持续对象和阅读目的要清楚。细微呼吸、背景自转、漂浮不计作已经实现内容变化。

## 4. 先排声音中的重点，再排运动

以原声和 SRT 的时间映射为依据，划分建立、主要变化、阅读停留和交接。句级 SRT 只提供句级边界：需要卡准某个词时听取对应片段并记录落点，不能把均分字幕时间伪装成词级对齐。

- 主体在被讲到时已能辨认，关键关系的变化跟随相应转折或动词，不让重要结论提前完成很久。
- 给复杂图形留下稳定阅读窗口。窗口长度依物件/文字密度和实际播放体验决定，不统一套一个数字；来不及就减少同时出现的次要项或分阶段展开，不改快原声。
- 动作开始时间、持续时间与最终停留都在同一计划里。背景持续运动不能掩盖前景等候过久；前景也不必每秒都有新动作。
- 新物件进入时先安排旧物件的职责和退路。下一句仍需解释/比较的锚点才保留并重排；只因曾经出现不能常驻，其他按生命周期退出；不能为了转场让所有对象同时弹跳或重生。
- 检查弹性峰值、路径中途和跨场双重可见时刻，具体方法沿用布局检查。动作只在开始/结束看起来正确还不够。

## 5. 动态小样通过后再扩展和导出

从本片选主要运动难点，制作带原声的短样片；可选连续镜头覆盖入场、关系改变和交接，无需固定长度或固定数量。自动制作授权下自行完成，不变成新的用户确认关卡。

记录并实际检查：

1. **设计延续**：动画中的主体仍用设计锁定的资产，阅读态保持认可的材质、主次和尺度。为运动调整的终态另有实图。
2. **语义变化**：看前/中/后真实帧或运行期测量，判断对应关系真的改变。代码目标值、文字承诺和单张完成态均不能代替观察。
3. **动作质感**：正速播放看起止、加减速、遮挡、跳变及停留；逐帧无碰撞不代表正速好看。高频晃动/重复弹跳若不服务意思就取消。
4. **音画同步**：带原声听相应片段，检查重点落点与读图时间。记录听审范围，不能用音轨存在或哈希一致冒称全片听审。
5. **可重复执行**：时间来自统一时间轴；正向/逆向 seek 到相同时刻状态一致，不靠 wall-clock、随机数或上一次播放残留碰巧通过。

发现失败回到对应层修复，检查受影响动作和相邻转场后再扩展。最终还要从实际编码成片抽帧并播放关键区间，防止浏览器预览与导出结果不同；完整检查要求见 [样片回归](regression-testing.md)。

## 6. 把失败写回方法，别把本集坐标写成规则

用户要求持续迭代时，维护简短的“问题 → 原因 → 修改 → 证据 → 适用边界”记录。一次失败可形成一条候选规则；先确认它是否只是实现错误，是否已被现有规则覆盖，再决定补规则、补检查或只修本期代码。

可迁移的修订应同时说明触发条件、应该改变的选择、如何实际观察是否解决，以及何时不适用。例如“组合增长需要独立成员”仅在成员自身需要出现/离开时适用，不推出“全部插图都必须拆件”。

复查已失败例和一个不会触发该规则的对照情形，防止修得过宽。重大的方法变化按授权做陌生文案前向试用；规划结果只能证明规划可用。规则、静态、动态、成片分别记录 `passed / failed / not_verified`，未做的动态或听审保持 `not_verified`。保留失败样本和修复后的真实产物后，才将证据支持的方法更新到正式 Skill；不能因写了新规则就宣称新片已通过。
