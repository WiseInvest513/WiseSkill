# 概念盘点与表现选择

新内容或因“名词只有文字框、图不传意”而重做视觉表达时，在匹配库存前读。局部修改只更新受影响的内容及承接。流程是：**全文提取 → 逐项选择 → 素材闭环 → 绑定实现 → 看实际画面**。

## 1. 先从全文识别，再看库存

提取承载信息的名词、实体和关键概念：公司/机构/人物、受众、地点、产品、操作对象、业务活动、指标、数额与单位、时间事件，以及需要解释的关系。不能只列公司Logo，也不能只登记已有图片的词。

合并同义称呼，保留规范名称、原文别称及所有出现的句/字幕编号。回查每句是否已处理，连接句可指向它承接的概念，不需为半句再造对象。代词要解析指向，普通口头连接语不变成素材任务。

区分相关但不同的对象：公司与股票、账户与现金、利润与股价、政策利率与国债收益率、某项功能与承载功能的设备。一个词在不同句承担不同角色时，记录用途差异，不因已有同名图而跳过。

词面匹配只用于找候选，必须读完整词组和上下文。例如“毛利率”不能因含“利率”就并入利率概念；“扩产”与“分配产能”分别改变总量与分配，不能仅因对象相同而合并。区分明确出现与真正承接，不把同段所有句子都列为每个概念的出处。

名词盘点不能取代命题理解。还要识别“如果、并非、增加、减少、比较、汇聚”等条件和变化；否则只是给旁白挂了一排图标。

## 2. 为每项作出表现决定

| decision | 用在什么地方 | 边界 |
| --- | --- | --- |
| `text` | 时间、单位、精确名称、短结论、章节导航或辅助标签 | 写明为什么文字足够、依附谁；“没图”“抽象”“省时间”不是降级理由 |
| `exact_identity` | 需要准确辨认的品牌、具体人物、真实产品/操作界面、位置 | 用可靠原件；概念图不得冒充官方标识、真人、真实页面或精确地点 |
| `concept_asset` | 业务活动、承载物、对象类别及可识别隐喻 | 图形实际内容须匹配含义；风格相似、文件同名不等于可用 |
| `data_chart` | 数量、价格、区间、趋势、比例或可计算例子 | 数据有依据，文字数字独立排版；示意不冒充真实时间序列 |
| `relationship` | 流程、比较、依赖、条件、归属、传递及机制 | 角色、连接和变化要成立；单独补一个图标不能交代关系 |

选择主要方式，允许结合其他方式；具体句中的变体写在原有句状态中。**决定必须说明理解收益，而非“丰富画面”。** 文字合理时可保留，图形有作用时才新增。语义上全量盘点，不等于每个词单独配图，也不要求每句换镜头。

例如，日期和币种通常是标签；“财报密集出现”需要报告与共同时间范围；“利润增长但估值压缩”需要两变量关系，财报插图本身不能解释；“总部在某地”需要定位，孤立建筑不足。

对候选图作替换检查：若把“财报”换成“认证”，图仍完全一样，确认它是否真的表达财报。带奖章的证书不是财报；普通银行不是某监管机构；钱包不是所有资金活动的统一答案。图和短标签合作，但标签不能强行改写图的含义。

## 3. 素材缺口不能被文字框掩盖

清单回答“需要解释什么”，素材索引回答“哪个文件能做到”。逐张打开候选图，核对可见内容、身份、材质、显示尺度和可动部件；不能仅按文件名检查存在性。

关系/数据图即使由代码实现，若方案引用尚缺的主物件，仍须登记该素材依赖；不能因“路线代码不缺”就忽略路线端点缺图。共享依赖按同一素材需求归并，不重复请求同一种图片。

每项最终落实为：已有素材适用；按授权取得/生成并查看；合理采用文字/代码图形而不依赖外部图片；或仍有明确缺口。继承已有补图授权，能继续就继续，不新增用户逐项批准流程。

关键视觉缺口未解决时，可继续盘点、取材及局部设计，**不能把缺口改成文字并标为完成后批量导出**。精确身份替代遵守原有授权规则；新原图补齐后同步引用，移除已失效的替代状态。通用概念可用准确的代码图解，无须把所有东西生成成位图。

## 4. 同一概念保持身份，状态随含义变化

首次建立识别后，重复使用同一视觉词汇；保持必要外观与角色，按本句重新决定聚焦、保留、变换或退出。重复名称不等于重复画面，身份连续也不等于物件一直占屏。

动作继续写在同一 `semantic_plan` 的对象、句状态和关系中，不另写隐藏时间表：

- 淡入/淡出解决出现与退出；缩放解决聚焦；这些不自动表达增长、压缩或传递。
- 流程要有起点、载体、终点；画出过程时能追踪到达及结果。静态依赖可以用静态箭头，不强迫所有线循环流动。
- 汇聚要形成共同范围/集合；数量与长度变化要有对应含义，没有数据就不暗示精确数值。
- 比较和计算要保留参照；条件、可能性在结果出现时仍有效。
- 风格与语义分别审查：漂亮物件不代表关系讲清，完整关系也不自动代表素材好看。

更多动作和布局要求沿用 [分析与编排](analysis-workflow.md)、[设计到动效](design-to-motion.md)，不因本次补图擅改已确认背景与署名。

## 5. 单份清单与两道检查

盘点保存为本期 `planning/concept-inventory.json`（沿用现有命名也可）；进入制作后 `semantic_plan.concept_inventory` 用 `{path, sha256}` 引用它，路径相对计划文件。**不复制两份概念真源。** 清单只记录判断和素材依据，动作/时间仍由原计划维护。

建议结构：

```json
{
  "schema_version": 1,
  "scope_caption_ids": [1, 2],
  "concepts": [{
    "id": "producer-price", "name": "PPI", "aliases": ["生产者价格指数"],
    "category": "经济指标", "caption_ids": [1],
    "decision": "concept_asset",
    "reason": "用生产端与价签区分消费端指标",
    "visual_role": "统计对象", "representation_hint": "工厂与出厂价签，缩写另排",
    "available_asset": [], "missing": true,
    "missing_detail": "现有库没有生产端价格素材"
  }],
  "source_coverage": [
    {"caption_id": 1, "concept_ids": ["producer-price"]},
    {"caption_id": 2, "concept_ids": [], "context_concept_ids": ["producer-price"], "text_only_reason": "承接上一句的判断"}
  ]
}
```

- `caption_ids`记录该概念所有明确出现位置；`context_concept_ids`单列间接承接，不能把整段都当成每个概念明确出现。
- 每项需有具体的`reason / visual_role / representation_hint`；`missing`真实表示该方案仍依赖的缺口，有缺口写`missing_detail`。
- `available_asset`引用实际本地文件，可相对项目根。文字、代码图表/关系无需外部图时允许空数组；`concept_asset`采用代码绘制时用`implementation_basis`说明可用组件。依赖数据/原件的图表仍要记其来源。
- `source_coverage`逐源句回查，不机械地给所有句绑定全部概念。无新增概念的句子可沿用明确参照或说明文字已足够。

运行只读检查（`--asset-root`为本期根目录）：

```sh
python3 scripts/validate_concepts.py INVENTORY.json --captions CAPTIONS.json --asset-root EP --stage planning
python3 scripts/validate_concepts.py INVENTORY.json --captions CAPTIONS.json --asset-root EP --stage assets
```

第一道检查允许尚缺素材，返回缺口；第二道检查要求缺口已落实。新计划在原计划校验之前执行这两步。旧项目不要求为历史归档补表；发生本次范围内重制时补齐相关范围。

脚本只检查ID、出处、覆盖接线和文件存在。它**不能证明概念提取完整、选择合理、图像可识别或有美感**；即使通过，仍须逐段对原文查漏、打开素材，并查看代表画面。

## 6. 实现后的验收

通过原有`render_bindings`和对象ID，回查重要概念在每次讲述中落到了什么实际主体/结构。检查计划选择了图像或关系，实际是否又退化为同名字卡；素材文件存在不代表它已上屏。

暂遮完整字幕但保留短标签，确认核心主体、比较依据或关系可辨；不是要求去掉所有文字也能懂。动作看前/中/后真实输出及原声，单张静态图不能证明连贯。

记录“规划通过、素材通过、实际画面通过、动态通过”的各自证据。未验证就写未验证，不以清单数量、图片数量或无碰撞代替结果。合理文字/静态对照也应保留，防止过度图解。

新增独立素材和关系组件按 [可复用素材](workspace-layout.md#可复用派生素材) 收敛，保留适用/不适用含义。下期复用含义和组件，不继承本期日期、数值或公司名单。
